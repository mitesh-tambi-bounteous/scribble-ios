# PADR-0001: Vibe-code the POC behind the generated harness

- Status: Accepted
- Date: 2026-06-29
- Type: Process ADR
- Deciders: Rob Forshier (with David Lawton on the S2D model)

## Context

The Scribl D2C POC is a roughly one-week clickable build on a locked Expo OSS
stack (see CLAUDE.md and the ratified P4 architecture). The build is done by AI
agents (Claude Code), not hand-set-up by a person. To keep the build on rails,
reproducible, and traceable to the ratified decisions, the project ships with a
generated harness rather than an ad-hoc, hand-written setup.

The harness (this `.claude/` tree, the root `CLAUDE.md` and `AGENTS.md`, and the
carried `decisions/` ADR set) is produced by HarnessBuilder (the development
environment / local Composer), verified against the B1 spec, and only then laid
down into this repo. HarnessBuilder is where harnesses are flushed out and
debugged; accepted harnesses promote toward Arc.Composer / OpenAgents (production).

## Decision

Vibe-code the POC behind the HarnessBuilder-generated harness.

- The skills, agents, and hooks under `.claude/` are generated by HarnessBuilder
  from a `mobile-app-poc` recommendation profile, not hand-written in this repo.
- The project `CLAUDE.md` and `AGENTS.md` and the architecture ADR set 0001-0011
  are carried verbatim from the ratified scribl project-DNA.
- This process ADR is authored fresh to record the decision.
- The launch-blocking invariants (AC2 submit-to-unlock, AC4 channel isolation)
  are encoded as skills owned by the `test-author` agent and enforced by the
  `invariant-guard` hook, so verification is part of the harness, not bolted on.

## Consequences

- The build is reproducible: regenerating the harness from the same profile
  yields the same jigs and fixtures.
- Improvements to the harness flow back into HarnessBuilder's catalog and the
  `mobile-app-poc` profile, so the next mobile POC inherits them.
- The harness is the contract: changes to the golden rules, locked stack, or
  launch-blocking invariants are made by re-generating or by an ADR, not by
  silent edits.
- The generated component layout follows standard Claude Code conventions
  (skills under `.claude/skills/<name>/SKILL.md`, agents as flat
  `.claude/agents/<name>.md`, hooks wired in `.claude/settings.json`).
