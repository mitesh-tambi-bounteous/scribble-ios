# Drawing-canvas performance spike (Skia) — testing procedure

**Why this exists.** The finger-on-glass drawing canvas is the highest-risk
component of Scribl (ADR-0006). Before the team commits a week to it, prove
`@shopify/react-native-skia` is responsive on a **real low-end Android device**.
The foundation ships only a *seam* (`components/canvas/`); this doc is the
playbook for the S-002 spike that fills it in.

This is a **cheap, throwaway-grade** spike. Do not build channels, persistence,
or the full drawing UX. Capture finger points, render strokes, watch for lag.

## What to measure
- **Stroke latency / dropped strokes** on a quick scribble — does the line keep
  up with the finger, or does it lag / drop segments?
- **Frame pacing** during continuous drawing (target: no sustained jank).
- **Export** — `makeImageSnapshot()` produces an image on the device (the
  drawing must be capturable for submit — S-003).

## Device bar (do NOT use an emulator or web for the verdict)
- Test on a **real low-end Android** device (e.g. a budget phone 2–3 yrs old,
  ~2–4 GB RAM). The emulator and web/CanvasKit hide native GPU behaviour.
- iOS device as a secondary check; iOS is rarely the constraint.

## Procedure
1. `npx expo prebuild` then `npx expo run:android` on the target device
   (no EAS — local build per CLAUDE.md).
2. Open the canvas route. Scribble fast, draw long continuous strokes, fill the
   screen, then `Clear` and repeat.
3. Record the result against the rubric below. Capture a screen recording.
4. Trigger `exportToImage()` and confirm a valid image comes back on-device.

**Web export prerequisite.** Before running `npx expo export -p web`, run
`npm run setup-skia-web` to fetch the CanvasKit wasm into `public/canvaskit.wasm`
(this file is gitignored and regenerated by the script, so it won't be present
on a fresh checkout).

## Rubric (record one)
| Verdict | Meaning | Action |
| --- | --- | --- |
| **Responsive** | No perceptible lag, no dropped strokes, smooth pacing | Proceed with Skia (one cross-platform codebase). |
| **Borderline** | Occasional lag on fast scribble; usable | Optimise (path batching, fewer re-renders); re-test before committing. |
| **Misses** | Visible lag / dropped strokes on low-end | **Fallback trigger** (ADR-0006): native canvas modules per platform + add a second mobile engineer. |

## Fallback trigger (ADR-0006)
If the low-end Android bar is missed, the locked decision is to fall back to
**native canvas modules per platform** and bring on a second mobile engineer.
Flag this immediately — it changes the staffing plan, not just the code.
